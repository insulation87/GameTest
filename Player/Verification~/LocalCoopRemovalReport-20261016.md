# 移除同機雙人

2026-10-16，Unity 6000.3.10f1。

## 修改

- 多人選單移除「開始同機雙人」、第二位角色欄與手把／備用鍵盤說明。左側只選自己的角色，右側保留區域網路與網際網路的建立／加入房間。
- 主選單及遊客訊息移除同機模式宣傳；角色仍有 10 種可選。
- 移除 `CoopMode.SplitScreen`，保留原來單人 0、房主 2、加入者 3 的 ID，舊值 1 不再代表有效模式。移除第二位本機角色生成及左右分割視窗，每台電腦只保留一名本機玩家與完整畫面。
- `SpawnActor` 拒絕建立額外本機角色。舊 `StartSplit` 僅保留給歷史 Editor 測試的編譯相容入口，固定回傳失敗，不載入場景、不建立玩家、不中斷既有網路房間。
- 移除第二組鍵盤／手把輸入框架、第二組鍵位頁及專用選單導覽。設定只呈現鍵盤與滑鼠，舊第二位玩家不再占用可綁定按鍵。保留設定資料結構供舊資料反序列化，原主玩家的自訂鍵位繼續沿用。
- 網路玩家的相機、HUD 與角色模型仍使用原本的本機／遠端顯示規則，本機視窗統一完整畫面。
- 更新多人、設定與像素相機說明及多人選單預覽。歷史同機測試在文件中標示為已退役情境。

## Play Mode 結果

全部測試在暫存目錄的完整獨立專案執行。使用獨立 company/product 與執行期指定的隔離存檔路徑，沒有進入使用者原專案的 Play Mode、儲存原場景或操作原存檔。

| 情境 | 通過 |
| --- | --- |
| 單人、設定、實際登入與主選單 | 33 |
| 獨立 TCP 房主程序 | 12 |
| 獨立 TCP 加入者程序 | 13 |
| 合計 | **58** |

單人測試使用正式 Map1，確認只有一位玩家；虛擬 Input System 鍵盤實際移動玩家。第二組鍵盤及手把無法產生操作框架或額外角色；設定只有一組，改綁原第二位玩家占用的 PageUp 後可儲存、載入並產生技能輸入框架，角色技能也實際執行。鍵位讀取與技能施放分別驗證，未宣稱人工按鍵試玩。

經過真實登入場景切換遊客，再進入主選單並點開多人選單：沒有同機入口、第二位角色與相關說明；10 位角色可完整循環，遊客仍可選 LAN，網際網路仍要求登入，連接埠錯誤能正確攔截。檢查退役入口無法載入場景，舊生成 API 無法增加本機玩家。

兩個獨立 Unity Editor Play Mode 程序透過 loopback TCP 進入正式 Map1：房主與加入者各只有一名本機角色、完整畫面，客戶端像素相機保持完整視窗。即使呼叫舊同機入口也不會取代正在進行的網路房間。另驗證遠端初期升級、三格配裝、遠端回聲輸入與實際投射物、裝備同步、盾牆提示、事件鑰石與商人後續影響同步。

兩張 1920×1080 實際 UI 渲染圖已目視檢查：`local-coop-removal-menu-20261016.png`、`local-coop-removal-settings-20261016.png`。多人選單正式預覽也已更新。沒有非預期遊戲執行期錯誤；原場景的雙 AudioListener 警告未在本次修改。

測試前幾輪調整了測試程式的 Input System 列舉、手動更新邊界與登入頁自動跳轉等待，最後完整重跑通過；這些調整未改動遊戲登入保護或技能操作程式。

未驗證：兩台實體電腦 LAN、公開網際網路中繼、四人完整遊玩、Windows 匯出執行檔與長時間效能。
