# 單人與多人合作

主選單左側保留單人開始、繼續遊戲與新遊戲流程；右側「多人模式」可選擇同網路合作，或登入帳號後使用網際網路房間。各玩家可選擇 10 位角色中的任何一位，也可以使用相同角色。

| 身分 | 單人 | 同網路多人 | 網際網路房間 | 好友 |
|---|---|---|---|---|
| 遊客 | 可以 | 可以 | 需登入 | 需登入 |
| 登入帳號 | 可以 | 可以 | 中繼服務啟用後可用 | 好友 SQL 啟用後可用 |

登入頁提供「以遊客身分遊玩」。遊客進度在 `Guest/progress-v1.json`，與帳號及既有進度隔離；可從主選單「返回登入帳號」切換。切換只能在主選單進行。

## 網際網路房間與好友

登入後選擇「網際網路」，建立房間取得 10 碼代碼，分享給朋友即可加入。朋友可使用不同的網路，不需設定玩家端的路由器。房間最多 4 人，密碼可留空；房主離開則其他玩家返回主選單。遊戲畫面底部顯示房間代碼。

主選單「好友」提供 12 碼好友代碼、暱稱、邀請／接受／拒絕／取消／移除與好友清單。好友資料儲存在現有 Supabase 專案；只有收到邀請的一方能接受。遊客無法查詢或操作好友。加入多人仍使用房間代碼，不提供好友一鍵加入或訊息聊天。

**公開中繼已設定**：`Resources/CloudRelayConfig.json` 使用 `wss://gametest-relay.onrender.com/coop`。2026-10-09 公開 `/health` 回應 HTTP 200、`status=ok`、`protocol=1`；Unity Play Mode 已驗證真實 HTTPS/WSS 連線及無效登入拒絕。好友 SQL 是獨立的好友功能，並非建立中繼房間的前置條件。

Render 免費服務休眠後需要喚醒。試玩前先開啟 [健康檢查](https://gametest-relay.onrender.com/health)，等看到 `status=ok` 再進遊戲，避免冷啟動超過目前 10 秒的 WebSocket 連線逾時。兩位玩家都需登入已驗證信箱的帳號，房主建立房間後分享 **10 碼房間代碼**；朋友在網際網路模式輸入代碼及相同密碼加入。原本已建置的執行檔不會讀取 Unity 專案中更新的設定，需使用新建置。

目前公開測試使用無效測試令牌，不使用真實帳號或建立公開房間；兩個真實帳號的建立／加入、遊戲同步與家用網路／手機熱點試玩仍需驗證。部署與維護步驟見 [Render 指南](RelayServer~/RenderGuide.md)。

## 每台電腦一位玩家

同機雙人已移除；每位玩家使用自己的完整畫面、角色、相機、生命、背包與技能。在多人選單左側選擇自己的角色，再於右側建立或加入網路房間。

移除後已在隔離 Play Mode 通過 58 項單人、選單及雙程序 TCP 驗證，詳見 [移除實測](../Player/Verification~/LocalCoopRemovalReport-20261016.md)。

操作使用本機的鍵盤與滑鼠，可在「設定 → 自訂鍵位」修改。第二位本機玩家的角色欄、手把／備用鍵盤配置與分割畫面入口均已移除。

## 丟棄裝備給隊友

開啟裝備背包，選擇物品後按「丟棄武器」或「丟棄防具」。裝備會出現在角色面前的地面，隊友靠近即可自動拾取；接收者再從自己的背包装備。武器與防具的名稱、等級、品質和數值完整保留，角色的武器適性規則仍適用。

已裝備的物品會自動卸下，武器切換至其他持有的武器；若丟棄最後一把武器，角色會暫時空手，重新拾取後自動裝備。丟棄者需先離開拾取範圍，才能撿回自己的掉落物，避免自動吸取直接把裝備收回。隊友死亡或背包已滿時不會消耗地面裝備；前方沒有可放置的地面或被牆壁擋住時，裝備仍留在背包。

同網路與網際網路房間使用相同的轉交流程。連線由房主核對物品身分並產生掉落物，客戶端等待房主確認後更新背包，重複送出的丟棄請求不會複製裝備。

## 同網路合作

房主選擇「同網路」、角色、連接埠（預設 TCP 25565）及可選的房間密碼，點擊「建立房間」。其他玩家選擇自己的角色，填入房主區域 IPv4、相同的連接埠與密碼，點擊「加入房間」。每台電腦可以登入帳號或使用遊客模式。

遊戲畫面底部會顯示房間人數；房主也會看到自己的區域 IP 與連接埠，可提供給同網路的朋友。

- 同一台電腦測試兩個遊戲實例時可用 `127.0.0.1`。
- 同一區域網路使用房主的區域 IP。
- 同網路傳輸會檢查本機介面網段，拒絕公網 IP、DNS 主機名稱與不同網段來源。房主仍需允許區域網路的遊戲防火牆連線。跨網路請登入並選擇網際網路房間。
- 房間最多 1 位房主加 3 位加入者，每台電腦只操作一位玩家。

房主負責移動、戰鬥、敵人、掉落、拾取、背包交易與升級判定。加入者只送出操作和限定的背包指令；敵人與動態物件的生成模型、位置和顏色由房主同步。畫面位置做平滑插值，沒有客戶端移動預測，因此操作延遲取決於與房主之間的網路延遲。連線模式的個人選單、升級和死亡不會暫停其他玩家；擊敗首領仍顯示通關畫面。

離開的玩家會從房間移除。房主離開或連線逾時時，加入者返回主選單；沒有房主轉移功能。

## 進度

多人入口每次開始新的一局，並保留單人存檔。房主的角色及共用世界進度使用該帳號的 `coop-v1.json`，原單人 `progress-v1.json` 不會被多人流程覆寫。加入者不會讀取或寫入本機單人進度。多人重新連線不恢復上一局的其他玩家角色狀態。

## 維護與驗證

`CoopSession` 管理模式、玩家與場景生命週期；`CoopInput` 分派操作；`CoopActor` 綁定個人相機與 HUD；`CoopTransport` 使用背景執行緒傳送有長度標頭的壓縮 UTF-8 訊息，限制訊息大小與佇列，所有 Unity 操作留在主執行緒。`CoopWorldMirror` 共用生成模型資料，後續同步位置和材質色彩。

`CoopModeReview.Run` 與舊的同機情境屬於移除前的歷史驗證。現行測試使用 `Player/Verification~/LocalCoopRemovalReview.cs.txt` 及 `LocalCoopRemovalNetworkReview.cs.txt`，在隔離暫存專案進入 Play Mode 驗證單人、選單、鍵位與兩個獨立程序的網路合作。不要在正式專案或未儲存的場景執行歷史測試。

`CoopNetworkPairReview.RunHost` 與 `RunClient` 在共用上層資料夾的兩個獨立暫存專案執行，驗證真正的房主／加入者載入、操作回傳、背包與升級同步，以及房主離線後返回主選單。這些入口也會建立測試場景，不能在正式專案執行。

驗證紀錄：55 項多人整合、18 項獨立房主／加入者、16 項相機清晰度，以及 91 項登入與單人流程檢查通過；改鍵另通過 30 項整合檢查，加入者的自訂操作亦已透過雙程序連線驗證。選單預覽已由 Unity 實際渲染並檢查。測試使用暫存場景、假登入服務與本機 TCP，不會寫入玩家正式存檔。正式地圖的多人長時間遊玩、跨網路連線及延遲表現仍需在實際遊戲環境驗證。

保留既有 Unity Input System 與網路傳輸套件；移除同機模式不需要新增套件。

歷史版本的草原／森林 Map1 曾完成兩個獨立 Unity 程序的 Play Mode TCP 連線，以及 Windows 非 Development 成品的單人、同機雙人與雙程序連線實測；同機模式已在 2026-10-16 移除。加入者現在由 CoopSession 初始化區域目標、傳送門及小地圖，避免跳過存檔流程後缺少指引。成品渲染以真正遊戲相機的離屏圖片驗證；外網、長時間遊玩與人工視窗操作仍未驗證。完整結果及建置套件診斷見 [OverworldNetworkBuildReport.md](../Dungeon/Editor/OverworldNetworkBuildReport.md)。
